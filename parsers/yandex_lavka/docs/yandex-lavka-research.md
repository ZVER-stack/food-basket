# Исследование Яндекс Лавки

Дата проверки: 2026-09-26.

Тест проводился в гостевой сессии на публичном адресе `Москва, Тверская улица, 1`.
Оформление и оплата заказа не выполнялись.

## Вывод

Основной сценарий воспроизводится прямыми HTTP-запросами. Playwright не нужен для
поиска, создания корзины, изменения количества и получения итоговой суммы.
Браузер может остаться резервным способом на случай изменения механизма гостевой
сессии или появления обязательной интерактивной проверки.

## Найденные запросы

| Действие | Метод | Путь |
|---|---:|---|
| Получить гостевую сессию и CSRF | GET | `/` |
| Подсказки адреса | POST | `/api/v1/providers/geo/v1/suggest` |
| Геокодировать адрес | POST | `/api/v1/providers/geo/v1/geocode` |
| Определить склад и доставку | GET | `/api/v1/providers/v2/service-info` |
| Поиск товаров | POST | `/api/v1/providers/search/v3/lavka` |
| Получить товары по ID | POST | `/api/v1/providers/v1/products/list/by-id` |
| Создать/прочитать корзину | POST | `/api/v1/providers/cart/v1/retrieve` |
| Обновить корзину | POST | `/api/v1/providers/cart/v1/update` |
| Очистить корзину | POST | `/api/v1/providers/cart/v1/drop` |

Также веб-приложение использует `/api/v1/providers/v1/state`, каталожные запросы
`main`, `layout`, `category` и `category-group`, но для минимального адаптера они
не требуются.

## Сессия и заголовки

Гостевая сессия создаётся обычным GET главной страницы. Из `window.__PAGE_PROPS__`
берутся два короткоживущих значения:

- `authProxyCsrfToken` → `X-Csrf-Token`;
- `csrfToken` → `X-Csrf-Token-Bff`.

Также запросы веб-клиента отправляют:

- `X-Lavka-Web-Locale: ru`;
- `X-Lavka-Web-City: 213` для Москвы;
- `Origin` и `Referer` домена Лавки;
- cookies той же гостевой сессии.

Токены и cookies не сохраняются в файлы и не должны попадать в логи. POST без
CSRF-заголовков был отклонён с HTTP 401 и сообщением `[Csrf] Successful blocking`.

## Адрес и склад

`geo/v1/geocode` принимает строку адреса и вернул для теста:

- город, улицу и дом;
- `buildingId`;
- координаты `lon`/`lat`;
- внутренний URI геообъекта.

Во всех запросах `position.location` имеет порядок `[longitude, latitude]`.

`service-info` принимает адрес и координаты. На момент проверки для тестового
адреса и `depotType=supermarket` сервис вернул:

- открытый склад `2025080603`;
- валюту `RUB`;
- интервал `10–40 мин`;
- высокий спрос;
- фактическую доставку `0 ₽`;
- отображаемую полную стоимость доставки `559 ₽`;
- минимальную сумму `0 ₽`.

Эти значения динамические и не должны фиксироваться в коде.

## Поиск

### Витрины

Веб-интерфейс разделяет ассортимент на несколько витрин. API принимает значения:

- `regular` — «Лавка у дома»;
- `supermarket` — «Большая Лавка»;
- `cafe` — кафе, не включается в основное продуктовое сравнение.

У `regular` и `supermarket` могут отличаться склад, ассортимент, цена, порядок
поисковой выдачи и условия доставки. Поэтому парсер возвращает `depot_type`,
`storefront` и `depot_id` для каждого товара. Для сравнения продуктовых корзин
нужно выполнять два отдельных поиска и два отдельных расчёта корзины; смешивать
позиции витрин нельзя.

При проверке запроса «Молоко 3,2% Село Зелёное» интерфейс «Лавки у дома» сначала
показал другие молочные товары. Прямой API-поиск при этом вернул нужное молоко на
четвёртом месте. Значит, отсутствие товара на первом экране не означает отсутствие
в ассортименте, а порядок API и интерфейса не всегда полностью совпадает.

Тело запроса содержит:

```json
{
  "additionalData": {"city": "Москва", "street": "Тверская улица", "house": "1"},
  "text": "молоко 3,2%",
  "position": {"location": [37.6147157174475, 55.75631527958286]},
  "productsLimit": 20,
  "subcategoriesLimit": 10,
  "geoId": "<buildingId>",
  "depotType": "supermarket",
  "useRetail": true,
  "source": "manual_input",
  "currencySign": "₽"
}
```

Ответ содержит `layoutItems`, `cacheProducts`, `offerId`, `x-yarequestid` и
`x-yatraceid`. Стабильный идентификатор товара находится в `cacheProducts[].id`.

Пример первого результата во время проверки:

- ID: `5b6c7a8f40a641fabf7ed0d225bbce26000400020002`;
- название: «Молоко 3,2% Лебедянь молоко»;
- текущая цена: `118` рублей;
- старая цена: `169` рублей;
- наличие: `true`.

## Корзина

`cart/v1/retrieve` без `cartId` создаёт отдельную гостевую корзину. Ответ содержит:

- `cartId` и монотонный `cartVersion`;
- `nextIdempotencyToken`;
- позиции;
- цены и скидки;
- доставку и ETA;
- минимальную сумму и доступность checkout.

`cart/v1/update` требует текущие `cartId`, `cartVersion` и
`nextIdempotencyToken`. Для товара передаются ID, количество, актуальная цена,
валюта, `pricePerCount` и `quantityType`.

Проверенная последовательность:

| Шаг | Версия | Количество | Итог |
|---|---:|---:|---:|
| Добавление | 2 | 1 | 118 ₽ |
| Изменение количества | 3 | 2 | 236 ₽ |
| Удаление | 4 | 0 | 0 ₽ |

После добавления выполнен отдельный `retrieve` с тем же `cartId`: версия,
позиция и итог совпали с ответом `update`.

В тестовой корзине с одной единицей товара:

```text
товары до скидки: 169 ₽
скидка:             51 ₽
доставка:            0 ₽
итог:              118 ₽
```

Переход к оплате в гостевой сессии ведёт на авторизацию Яндекса. Адаптер туда не
переходит.

### Несколько вариантов доставки

Корзина может одновременно предлагать несколько логистических вариантов. Для
проверенного адреса были доступны:

- `onDemandDeliveryInfo` — «Сейчас», 30–60 минут;
- `personalLogisticDeliveryInfo` — «Подождать», до 120 минут.

Оба варианта показывали доставку 0 ₽. Однако условия невыбранного варианта в
ответе корзины являются предварительными. До переключения медленной доставки
API указывал минимальную корзину 3 000 ₽. После выбора этого режима интерфейс
пересчитал минимум до 4 500 ₽ и показал, что к корзине 219 ₽ нужно добавить ещё
4 281 ₽. Поэтому адаптер помечает выбранный вариант как `confirmed`, остальные
как `preview`. Для окончательного сравнения альтернативный вариант необходимо
выбрать отдельным запросом и повторно прочитать корзину.

Переключение выполняется тем же `POST /api/v1/providers/cart/v1/update`. В тело
передаются текущие `cartId`, `cartVersion`, `nextIdempotencyToken`, пустой массив
`items` и флаг:

```json
{
  "personalLogisticSelected": true
}
```

После обновления корзина повторно читается через `retrieve`. Живая проверка
подтвердила результат: выбран `personal`, ETA — «до 120 мин», доставка — 0 ₽,
минимальная корзина — 4 500 ₽, для корзины 219 ₽ не хватает 4 281 ₽. Поле
`availableForCheckout` при этом равно `false`.

## Ограничения и риски

- API внутренний и не документирован публично, поэтому его контракт может измениться.
- CSRF-токены короткоживущие; каждый расчёт использует новую гостевую сессию.
- Ассортимент, цены, склад, ETA и доставка зависят от адреса и времени.
- В обычных запросах не наблюдались `429`, `Retry-After` или CAPTCHA; нагрузочное
  тестирование не проводилось.
- При первой CAPTCHA адаптер должен остановиться с `ANTI_BOT_CHALLENGE`, без обхода.
- Поле `totalDiscountValue` не совпало с визуальной скидкой корзины; для нормализации
  используется проверяемая разница `price.full.number - price.items.number`.
## Каталог по категориям

Для адреса `Москва, Рязанский проспект, 2к2` подтверждена следующая цепочка
гостевых запросов:

1. `POST /api/v1/providers/v1/layout` — дерево групп и категорий витрины;
2. `POST /api/v1/providers/v2/category` — все карточки одной категории и дерево
   подкатегорий;
3. `POST /api/v1/providers/v1/product` — подробная карточка, включая состав,
   описание, бренд, фасовку и КБЖУ, когда они заполнены источником.

Каталог зависит от `depotType`, координат и выбранного склада. Поэтому
`regular` и `supermarket` сохраняются как разные предложения, даже когда у них
совпадает `product_id`.

Контрольный полный проход 8 октября 2026 года дал:

- `regular`: 51 продуктовая категория, 3 831 уникальное предложение;
- `supermarket`: 53 продуктовые категории, 5 942 уникальных предложения;
- 6 879 уникальных `product_id` между двумя витринами.

Ответ категории на этом адресе возвращает полный плоский массив `products` без
отдельной пагинации. Один товар может входить в несколько категорий, поэтому
связи сохраняются в `product_categories`, а сами предложения дедуплицируются по
`(service, depot_type, depot_id, product_id)`.

На первом снимке все перечисленные карточки имели `available=true`: внутренний
каталог не перечисляет неизвестные сборщику отсутствующие SKU. Такие товары
можно сохранять в следующих снимках, если они были замечены раньше, и повторно
проверять через подробную карточку с `enableUnavailable=true`.
