# Ozon Fresh: состояние реализации

**Это незавершённая интеграция, а не полная выгрузка.** Ваш HAR уже обработан:
получены 208 наблюдений по двум адресам, в том числе 138 строк с известной обычной
ценой и упаковкой. Подробности — в README_HAR_RESULT.md. Все 197 зон ещё не
собраны. Лимит в 2 часа не измерен и не подтверждён.

17 октября 2026 года публичный API попал в цикл HTTP 307, а отдельный анонимный
Chrome, запущенный через Playwright, получил HTTP 403 / Antibot Challenge Page.
Сбор остановлен. Автоматический инструмент управления обычным Chrome сначала не
смог определить URL окна, затем сообщил об остановке через Esc. Пользователь
сообщил, что вручную Fresh открывается, включая режим инкогнито.

## Что сделано

- Изучены README, шаблон и все 201 гексагон из SNO_students.
- Используются адрес и координаты **дома**, а не центра гексагона.
- Исключаются 4 зоны с `address_in_zone=False`; остаются 197 зон.
- Новый сборщик получает страницы каталога через JSON, без открытия каждой карточки.
- Источники категорий задаются проверенным списком конечных категорий продуктов и
  бытовой химии. Нечёткий поиск по словам вроде «рис» и «мед» не используется.
- После установки адреса координаты проверяются по ответу сервиса. Несовпадение
  более чем на 100 м останавливает проход. Автоматическая замена дома не реализована.
- Каталоги кешируются по явному ID склада и серверной области цен, если она есть.
  Без области цен повторное использование между зонами отключено. Его можно
  включить только после проверки, что склад определяет полный набор предложений.
- Стоимость, минимум и время доставки берутся заново для каждого адреса.
- Прогресс сохраняется в SQLite после страницы и после зоны. Повторный экспорт
  атомарный, без добавления повторов. Возобновление допустимо в пределах того же
  двухчасового снимка с теми же входными файлами и конфигурацией.
- Цена обычной покупки, зачёркнутая цена и цена по карте разделены. Цена по карте
  не подставляется вместо обычной. Размер упаковки обязателен.
- Неполная карточка, неизвестное окончание пагинации, конфликт цен или пустой каталог
  при наличии доставки останавливают проход. Они не превращаются в «нет доставки».
- CSV содержит ровно 37 колонок шаблона, UTF-8, запятые, московские даты.
- Ограничение запросов общее, минимум 1 с между началами запросов, без параллельной
  сетевой нагрузки. При 401/403/429, редиректе или распознанной странице защиты — стоп.
- 45 тестов проходят: проверки общего транспорта и три настоящих примера карточек
  из анонимного HAR. Это проверка логики и записанного формата; живой полный
  проход по 197 зонам пока не подтверждён.

Старые скрипты и исходный CSV не изменены. Новый код добавлен в `fresh_fast`.
Для основной реализации достаточно стандартной библиотеки Python 3.11+.

## Что ещё требуется

Анонимный HAR для двух домов получен и разобран. Остаются живая проверка
адресного протокола, получение обычных цен для CARD_PRICE, полная пагинация,
уточнение бытовой химии и пробный проход. ID склада в исследованных ответах
не найден: он необязателен для CSV, но без него каталоги между зонами не кешируются.

Файл `contract.unconfigured.json` намеренно выключен. Пустые разделы — обозначение
неподключённой интеграции. **Не меняйте только флаг `verified_anonymous_contract` на
true:** это не делает контракт проверенным. Нельзя считать код готовым парсером,
пока не заполнены реальные запросы, JSON pointers, точный список категорий Fresh
и не пройден живой тест на 3–5 разных адресах.

## Если понадобится дополнительная запись из Chrome

1. Открыть новое окно инкогнито, не входить в аккаунт.
2. Открыть DevTools → Network, включить Preserve log.
3. Открыть Fresh, выбрать первый дом из `inhabited_zones.csv`.
4. Открыть категорию продуктов и пролистать несколько страниц, затем бытовую химию.
5. Сменить адрес на другой дом из файла и открыть ту же категорию.
6. Сохранить HAR **с телами ответов**, предпочитая встроенный вариант без
   чувствительных заголовков. Не включать вход в аккаунт, заказы и платёжные данные.

HAR нужен для локальной настройки, он не включён в архив результата. Сохранённый
HAR можно сначала исследовать:

```powershell
..\.venv\Scripts\python.exe .\ozon_fresh_fast.py inspect-har --har .\public.har --out .\work\har_inspection.json
```

Команда не копирует заголовки авторизации или cookies; удаляет поля с именами,
похожими на токены и идентификаторы сессии. Это не универсальная гарантия
обезличивания произвольного HAR: исходный файл лучше использовать только локально.
Сводка сохраняет названия query-параметров без значений, поэтому для восстановления
точного запроса используется исходный локальный HAR.

## Контракт

- `set_location`: фактический запрос публичной витрины, `method`, `url`, `json`.
  Подстановки `{lat}`, `{lon}` сохраняют числовой тип в JSON; `{address}` — текст
  адреса дома. Подстановки внутри URL кодируются. Не допускаются внешние домены,
  авторизационные заголовки и запросы вне путей витрины.
- `context`: запрос, подтверждающий выбранный дом и условия Fresh.
- `context_schema`: обязательные JSON pointers `lat`, `lon`, `delivery_available`;
  `store_id` необязателен. Дополнительно `delivery_eta_min`, `delivery_fee`, `min_order`, `price_scope`.
  Доставка — явный boolean, отсутствие поля не означает отсутствие доставки.
- `catalog_schema`: `widget_prefix` основного каталога (если используется), `items`
  внутри него, `next` с серверной ссылкой на следующую страницу. `next_from_root`
  указывает, читать ли `next` из корня ответа. Поле последней страницы должно
  присутствовать и содержать null или пустую строку. Поиск товара во всех вложенных
  рекомендациях не выполняется.
- `card_mapping`: JSON pointers относительно одной карточки. Обязательно настроить
  `product_id` или `url`, `name`, обычную `price`; желательно явную `amount`.
  `price_regular` при отсутствии равна `price`. Нестандартные поля уйдут в `extra`.
- `categories`: проверенные конечные категории, каждая с `category_id`, `name`,
  `url` с `miniapp=supermarket`, `scope` (`food` / `household_chemicals`),
  `verified_leaf=true`. Корень «Бытовая химия и гигиена» целиком не подходит:
  нужны отдельные ветки химии без косметики и прочих ненужных товаров.
- Если даже внутри категории встречается маркетплейс, настроить проверенное поле
  `fresh_item_pointer` и `fresh_item_value` в `catalog_schema`. Одного параметра
  `miniapp=supermarket` недостаточно для доказательства принадлежности к Fresh.
- Если есть поле склада в каждой странице, указать `catalog_store_pointer`.
- `warehouse_defines_full_offer=true` допустим только после отдельной проверки,
  что один склад означает одинаковые цены, наличие и ассортимент для этих адресов.

## Команды

Из каталога `PythonProject\fresh_fast`:

```powershell
# Офлайн-проверки
..\.venv\Scripts\python.exe -m unittest -v test_ozon_fresh_fast

# Сценарная оценка числа запросов. Это НЕ замер скорости.
..\.venv\Scripts\python.exe .\ozon_fresh_fast.py plan --zones .\inhabited_zones.csv --stores 20 --pages 150

# Только ПОСЛЕ настройки контракта — проба на 5 зонах
..\.venv\Scripts\python.exe .\ozon_fresh_fast.py run --zones .\hexagons.csv --contract .\contract.json --limit 5 --state .\work\pilot.sqlite --out .\results\pilot.csv

# Полный новый снимок; время и бюджет запросов относятся ко всем возобновлениям
..\.venv\Scripts\python.exe .\ozon_fresh_fast.py run --zones .\hexagons.csv --contract .\contract.json --seconds 7200 --interval 1.05 --max-requests 6800 --state .\work\full.sqlite --out .\results\ozon_fresh_2026-10-17_SURNAME.csv

# При прерывании повторить ту же команду в пределах 2 часов с начала снимка
# Проверка полноты всех 197 зон:
..\.venv\Scripts\python.exe .\ozon_fresh_fast.py validate --zones .\hexagons.csv --csv .\results\ozon_fresh_2026-10-17_SURNAME.csv
```

Фамилию в итоговом имени надо заменить на настоящую. У ограниченного пилота
`complete=true` в отчёте означает только завершение выбранных 5 зон. Проверка
`validate` относительно полного `hexagons.csv` отдельно проверяет все 197 зон.

## О двух часах

Текущие 6 852 карточки уже превышают комфортный бюджет, если запрашивать каждую
отдельно даже для одного магазина. Поэтому основной путь — страницы каталога,
без необязательного КБЖУ и описаний с индивидуальных карточек. Обязательные поля
всё равно должны быть заполнены; если их нет в каталоге, потребуется измерить
стоимость дополнительного обогащения или признать ограничение двух часов
недостижимым при действующих правилах.

Сначала измеряются 3–5 зон, число уникальных складов и страниц на склад, полнота
категорий и обычная цена относительно UI. Затем оценивается весь проход.
Если лимит времени исчерпан, выгружаются только полностью подтверждённые зоны,
а `.report.json` перечисляет результат и причину остановки. Таймер ограничивает
сетевой этап; завершение текущего запроса и запись CSV могут добавить время.
Оставшиеся зоны не заполняются выдуманными данными.

Данные зон: OpenStreetMap contributors, ODbL, как указано в исходном SNO_students.
