# Режим справочника SKU: обновление 18 октября

По явному разрешению пользователя обычная цена может переноситься между адресами,
если совпали SKU, название, фасовка, наличие, тип цены и все видимые цены каталога.
Для такого переноса обязательны одновременно цена по карте и цена без скидки.
Это предположение исследования: обычная цена **не проверена на новом адресе**.

Первый полностью обойдённый адрес создаёт справочник. На следующих адресах:
- обходятся все страницы всех выбранных категорий;
- отсутствующие SKU не попадают в CSV этого адреса, но остаются в справочнике;
- новые SKU и изменившиеся предложения с недоступной обычной ценой проверяются по карточке;
- если обычная цена прямо показана в каталоге, используется она;
- совпавшие предложения используют ранее проверенную обычную цену с отметкой источника;
- более поздняя цена того же SKU заменяет предыдущую вместе со всей группой цен;
  предыдущее наблюдение сохраняется в extra. Противоречия в одно и то же время остаются ошибкой.

Сопоставление по SKU защищает от одинаковых названий разных упаковок.
Частично собранный адрес не считается готовым справочником. Справочник восстанавливается
из завершённых адресов snapshot.sqlite при продолжении того же прохода.

В extra перенесённой строки: ordinary_price_inferred=true,
ordinary_price_verified_for_address=false, ordinary_price_origin (адрес-источник,
время и способ получения), price_cache_match. parsed_at относится к чтению
каталога текущего адреса; исходное время цены хранится отдельно в origin.
При повторном использовании исходный источник сохраняется, цепочка не подменяет его.

Режим включён в 05_run_parallel.cmd. Для строгих подтверждённых по каждому адресу цен:
`python run_parser.py --action full --price-workers 3 --interval 3 --price-policy verified_each_address`.
07_resume_current.cmd продолжает только действующий снимок, не создаёт новый,
не продлевает бюджет и не сбрасывает блокировку доступа. При защите нужен прежний
порядок ручной проверки и файл06.

В live_report.json отдельно указаны inferred_ordinary_price_rows и
all_ordinary_prices_verified_for_address. Флаг complete означает полный обход
ассортимента; он не превращает перенесённые цены в проверенные на этом адресе.
Дельты SKU сохраняются в assortment_changes/<h3>.json только после полного обхода.

128 локальных тестов прошли. Если в плитке нет фасовки, читается явно показанное
количество из характеристик карточки; оно не используется для расчёта цены.
Неудачно разобранная плитка сохраняется локально в SQLite parse_failures для
диагностики без повторного запроса.

Новый режим проверен локально; фактические 35 секунд на дом и 197 зон за два часа
пока не подтверждены. Чтение всех страниц каталога по-прежнему требует запросов.

ручной проверки. Не меняйте адрес в Chrome во время сбора. Неполные страницы
сохраняются в SQLite и не выдаются за завершённую зону.
