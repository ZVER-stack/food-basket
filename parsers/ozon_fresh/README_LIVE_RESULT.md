## Доработки кода

- `ozon_browser_transport.py`: запросы через работающий пользовательский Chrome,
  общая пауза между запросами, запрет авторизованного профиля, остановка при
  защите. После 403 автоматического повтора внутри запроса нет. Отдельная новая
  проверка допускается после увеличенной паузы; повторения ограничены.
- `ozon_live_parser.py`: реальный адресный протокол, сверка дома и координат,
  пилот и строгий полный режим. Полная зона экспортируется только после всех
  категорий и заполнения обязательных полей. Если `CARD_PRICE` не содержит обычной
  цены, строгий проход обращается к странице товара в том же анонимном контексте.
  При защите, отсутствии подтверждённой цены или другого обязательного поля
  проход завершается с диагностикой, без подмены или скрытого пропуска.
- `ozon_product_prices.py`: чтение явных полей `webPrice.price`, `originalPrice`,
  `cardPrice`, как в исходном парсере. Проверяются название товара и адрес.
  Подходящий ответ встроенного HTML используется сразу; иначе JSON запрашивается
  из открытой страницы товара. Сначала проверяется статус документа: после 403
  запроса API нет. Цена из каталога по карте сохраняется, если на странице нет
  отдельного поля `cardPrice`. Разбор проверен локально на исходном сохранённом
  ответе; успешный живой проход с дополнительным чтением цен ещё не подтверждён.
- `ozon_fresh_fast.py`: сохранение страниц и зон, атомарный CSV, ограничение
  времени и числа запросов, запрет дубликатов и незаметной смены снимка.
- `ozon_har_catalog.py`: настоящий формат карточек, роли цен, обе формы пагинации,
  упаковка, рейтинг, отзывы, отображаемая скидка, ссылки без tracking-параметров.
- `testdata/live_address_protocol.json`: минимальные настоящие ответы успешной
  смены адреса; данные браузера, IP, cookies и токены в примеры не включены.

ID даркстора в исследованных данных не найден. Городской FIAS/UID и схема доставки
131 не выдаются за склад. Кеширование между адресами отключено.

## Дополнение: HAR карточки, сохранённый пользователем

В `product_prices.har` от 17 октября 2026 года, 15:30:15 МСК, HTML товара
2952307571 содержит все три явных поля: `price=199`, `originalPrice=215`,
`cardPrice=195`. Личный аккаунт не используется. Заголовок подтверждает
«Новощукинская ул., 2», гексагон `8711aa733ffffff`; кнопка предложения Fresh
содержит тот же SKU. Все три цены извлечены существующим модулем без изменения
правил значений. Пример очищен от tracking-параметров и добавлен в тесты.

Одна строка сохранена отдельно в `product_price_evidence.csv` рядом с этим
отчётом. Это запись из пользовательского HAR для указанного дома и времени,
а не успешный запрос нового транспорта или полный каталог зоны. Она не
подставлялась в результаты по Бакунинской улице.

У рабочего ответа есть параметр ссылки `sh` и участие Service Worker.
Проверка подключённого браузера показала, что Service Worker включён и там.
Для проверки отличий после паузы 774 секунды один раз открыта ровно записанная
публичная ссылка в существующей вкладке подключённого Chrome. Она вернула 403;
дальнейших запросов не было. Cookies, заголовки, прокси и профиль не заменялись.
Следовательно, по HAR пока нельзя утверждать, что проблема соединения исправлена
или что причина только в URL. Доступное подключение — порт 9223; порт 9222
недоступен. Рабочее окно пользователя к этому соединению не подключено.

Теперь дополнительно проверяется соответствие SKU и признака предложения Fresh
на странице товара, чтобы не взять цену другого продавца. Исходная логика чтения
цен подтверждена настоящим свежим ответом; остаётся получить рабочее подключение
к публичной браузерной сессии для живого пилота.

Данные собираются в формате «товар — гексагон». Формирование и сравнение корзины
в этот этап не входят. Метаданные кнопки добавления в корзину читаются только как
признак предложения Fresh; сами действия добавления не вызываются.

Состояние сохраняется в SQLite после страниц и завершённых зон. Полный CSV
записывается атомарно один раз при завершении запуска, чтобы не переписывать
уже собранные зоны после каждого адреса.

## Ограничение времени

Даже после сокращения маршрутов текущая схема требует минимум 4728 запросов:
197 × (5 для адреса + 18 первых страниц категорий + 1 проверка адреса в конце).
Это нижняя оценка для данного алгоритма, без следующих страниц и получения
недостающих обычных цен. При текущей увеличенной паузе 3 секунды это около
236 минут ожидания между запросами. Поэтому эта версия пока не выполняет
условие двух часов. Возврат к меньшей допустимой паузе сам по себе также не
доказывает достижимость цели: нужен полный замер и дальнейшее сокращение запросов.
Расчёт сохранён в `category_request_plan.json` рядом с этим отчётом.
